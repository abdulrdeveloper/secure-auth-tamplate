Full execution breakdown of the Express 5 + React 18 + Tailwind v4 + TypeScript authentication template with dual tokens (15 minute access + 7 day refresh). Step-by-step from the first page load to logout.

🚦 End-to-End User Journey Walkthrough

Jab koi user website par ata hai, files kis sequence mein load hoti hain aur backend ke kon se middlewares aur controllers chalte hain:

STAGE 00 node dist/server.js
0. Server Startup & Safety Checks
Koi request aane se pehle backend start hota hai aur check karta hai ke configuration sahi hai. Kuch bhi galat ho to server start hi nahi hota, taake galti chupi na rahe.
Env Checks

backend/server.ts

Required env missing ho to process exit: MONGO_URI, ACCESS_TOKEN_SECRET, REFRESH_TOKEN_SECRET, RESEND_API_KEY, Upstash keys, FRONTEND_URL, EMAIL_FROM, COOKIE_SAMESITE.

COOKIE_SAMESITE sirf lax ya none ho sakta hai, aur dono token secrets alag hone chahiye.

Database & App

backend/src/config/db.ts MongoDB connect karta hai, fail ho to exit.

backend/src/app.ts: trust proxy, CORS (FRONTEND_URL + credentials), express.json (10kb limit), cookie-parser, GET /health, aur /api/auth router.

Error Safety Net

backend/src/middlewares/error.middleware.ts sab routes ke baad lagta hai.

Unknown route: JSON 404. Galat JSON: 400. Bada body: 413. Koi bhi aur error: server log mein detail, user ko sirf Internal server error. Stack trace kabhi leak nahi hota.

STAGE 01 GET /api/auth/me
1. App Bootstrapping & Session Check
User browser mein app kholta hai. React mount hote hi AuthProvider ek dafa /me call karke pata karta hai ke user pehle se logged in hai ya nahi. Jab tak jawab nahi aata, route guards loader dikhate hain.
Frontend Entry Points

1. frontend/index.html (<div id="root"> aur favicon)

2. frontend/src/main.tsx (React root aur index.css)

3. frontend/src/App.tsx (BrowserRouter > AuthProvider > Routes)

Global Auth State

frontend/src/context/auth-context.tsx

State: user, loading. Functions: setUser, logout. Pages useAuth() se user lete hain, dobara /me call nahi karte.

Agar silent refresh fail ho to auth:session-expired event aata hai aur user khali ho jata hai.

Routing Decision

frontend/src/components/protected-route.tsx

PublicRoute: logged-in user /login, /register waghera khole to /dashboard.

ProtectedRoute: login nahi to /login, saath mein state.from taake login ke baad wapas usi page par aaye.

Unknown URL /dashboard par jata hai, aur wahan se guard faisla karta hai.

STAGE 02 POST /api/auth/register
2. New User Registration & OTP Issuance
User Register form bharta hai (Full Name, Email, Password). Backend rate limit aur validation ke baad password hash karta hai, OTP Redis mein rakhta hai aur Resend se email bhejta hai.
Frontend Execution

frontend/src/pages/auth/register.tsx

Calls: apiRequest("/auth/register", { method: "POST", data: form }) via frontend/src/lib/api.ts.

Response ka resendAfter (60) le kar startOtpCooldown() chalata hai, phir /verify-email?email=... par bhejta hai.

Middlewares

backend/src/middlewares/rate-limit.middleware.ts: IP par 15 minute mein 10 requests.

backend/src/middlewares/validate.middleware.ts + registerSchema (backend/src/config/validation.ts): name 2-100, email lowercase, password kam az kam 6.

Controller & Services

backend/src/controllers/register.controller.ts

Verified email ho to 400. Unverified user dobara register kare to name aur password update hote hain. verificationExpiresAt 24 ghante.

backend/src/services/otp.service.ts: 6-digit OTP, 300s expiry, 60s cooldown. backend/src/services/mail.service.ts: email bhejta hai. Email fail ho to OTP saaf aur 500.

STAGE 03 POST /api/auth/verify-email
3. OTP Verification & Automatic Sign-In
User email ka 6-digit code daalta hai. Backend attempts gin kar code check karta hai, account verify karta hai aur dono token cookies set karke user ko sign in kar deta hai.
Frontend Page

frontend/src/pages/auth/verify-email.tsx

OtpField sirf digits rakhta hai (paste kiya hua 123 456 bhi 123456 ban jata hai). ResendCode + frontend/src/hooks/use-cooldown.ts countdown dikhate hain.

Success par VerificationSuccess screen, 1.2s baad setUser() aur /dashboard.

Brute-Force Protection

backend/src/controllers/verify-email.controller.ts → verifyOtpWithRateLimit()

Code compare karne se pehle Redis INCR se attempt ginta hai. Is liye ek saath 30 galat requests bhi 5 se zyada guess nahi kar saktin.

5 galat attempts par OTP delete. Sahi code ek hi dafa use ho sakta hai.

Tokens & Cookies

backend/src/utils/token.util.ts: setAuthCookies(res, user._id)

Access JWT (ACCESS_TOKEN_SECRET, 15m) aur refresh JWT (REFRESH_TOKEN_SECRET, 7d, random tokenId). tokenId Redis mein refreshToken:<userId> par save.

backend/src/utils/user.util.ts: toPublicUser() sirf _id, name, email, isEmailVerified, createdAt bhejta hai.

STAGE 04 POST /api/auth/login
4. Returning User Login
User email aur password daalta hai. Backend password match karta hai, verified hone ka check karta hai aur naya session banata hai. Purana session (doosre device ka) khud khatam ho jata hai, kyunki ek user ka ek hi refresh token hota hai.
Frontend Form

frontend/src/pages/auth/login.tsx

Components: Field (Email), PasswordField (eye toggle).

Success par setUser(response.user), phir state.from ya /dashboard par.

Backend Controller

backend/src/controllers/login.controller.ts (rate limit: 15 minute mein 10)

1. userModel.findOne({ email }).select("+password")

2. bcrypt.compare(password, user.password), galat ho to 400

3. if (!user.isEmailVerified) 401

4. setAuthCookies(res, user._id)

STAGE 05 GET /api/auth/me
5. Protected Dashboard & Auth Middleware
Dashboard sirf ProtectedRoute ke andar render hota hai, is liye bina login wala user isse dekh hi nahi sakta. Backend par har protected request access cookie se check hoti hai.
Frontend Dashboard

frontend/src/pages/dashboard/index.tsx

useAuth() se user ka name aur email dikhata hai. GitHub links frontend/src/config/site.ts se aate hain.

Auth Middleware Guard

backend/src/middlewares/auth.middleware.ts

Sirf accessToken cookie padhta hai aur ACCESS_TOKEN_SECRET se verify karta hai. Refresh token yahan kaam nahi karta, kyunki us ka secret alag hai.

Valid ho to req.userId, warna 401.

Me Controller

backend/src/controllers/me.controller.ts

userModel.findById(req.userId) aur toPublicUser().

STAGE 06 POST /api/auth/refresh
6. Silent Refresh & Token Rotation
15 minute baad access token expire hota hai aur API 401 deti hai. User ko kuch pata nahi chalta: frontend chupke se refresh karta hai aur wahi request dobara bhejta hai.
Frontend Client

frontend/src/lib/api.ts: refreshSession()

401 aaye to ek shared promise se /auth/refresh call hota hai. 5 requests ek saath fail hon tab bhi refresh sirf 1 dafa chalta hai.

Refresh kaamyab: request dobara. Nakaam: auth:session-expired event, user login page par.

Backend Rotation

backend/src/controllers/refresh.controller.ts

1. verifyRefreshToken(): signature aur expiry check.

2. isRefreshTokenActive(): token ka tokenId Redis wale se match hona chahiye.

3. setAuthCookies(): naya access + naya refresh token. Purana refresh token ab reject hoga.

Reject Cases

Token missing, galat secret, expire, logout ho chuka, ya password reset ho chuka: dono cookies clear aur 401 Session expired.

STAGE 07 POST /forgot-password, /verify-reset-otp, /reset-password
7. Two-Step Password Recovery
Pehle email par reset code aata hai, phir code check hota hai, phir naya password save hota hai. Password badalte hi purana session bhi khatam ho jata hai.
Step 1: Request Reset Code

frontend/src/pages/auth/forgot-password.tsx

backend/src/controllers/forgot-password.controller.ts: hamesha same generic message aur resendAfter, chahe email ka account ho ya na ho. Is se pata nahi chalta ke kaunse emails registered hain.

Step 2: Verify Code

frontend/src/pages/auth/reset-password.tsx (email na ho to /forgot-password par wapas)

backend/src/controllers/verify-reset-otp.controller.ts: validateOtpWithRateLimit() code ko consume kiye baghair check karta hai.

Step 3: New Password

backend/src/controllers/reset-password.controller.ts

Code dobara check, password hash, clearOtp(), aur revokeRefreshToken(): purane sab sessions khatam.

STAGE 08 POST /api/auth/logout
8. Logout & Session Revocation
User "Sign out" dabata hai aur dialog mein confirm karta hai. Backend Redis se refresh token delete karta hai, dono cookies clear karta hai, aur frontend user ko login page par bhej deta hai.
Frontend

Dashboard ka confirm dialog useAuth().logout() chalata hai: /auth/logout call, phir setUser(null). ProtectedRoute khud /login par bhej deta hai.

Backend

backend/src/controllers/logout.controller.ts

Refresh token ko jwt.verify karta hai (sirf decode nahi), active ho to revokeRefreshToken(), phir clearAuthCookies().

Is liye nakli token bana kar koi kisi doosre ko logout nahi kar sakta.

🚧 ProtectedRoute / PublicRoute
⚡ api.ts (Silent Refresh)
⬇️ [HTTP / JSON / HttpOnly accessToken + refreshToken cookies] ⬇️
2. Express Server Tier (Port 3000)
🚀 server.ts (Env Checks)
🛡️ CORS (FRONTEND_URL)
🍪 cookie-parser
⏱️ rate-limit.middleware
📋 validate.middleware (Zod)
🔒 auth.middleware (Access JWT)
🧯 error.middleware
⬇️ [auth.routes.ts] ⬇️
3. Controllers & Utility Helpers
👤 register
✉️ verify-email / resend-otp
🔑 login / me
🔄 refresh
🧩 forgot / verify-reset / reset
🚪 logout
🧰 token.util (setAuthCookies)
🧹 user.util (toPublicUser)
⬇️ [Data & Storage Operations] ⬇️
4. Infrastructure & Database Tier
🍃 MongoDB (User schema + 24h TTL for unverified)
⚡ Upstash Redis (OTPs, cooldowns, attempts, refresh tokens, rate limits)
📧 Resend API (verification and reset emails)

🧠 Redis Keys

Redis mein sab kuch expiry ke saath save hota hai, is liye purana data khud saaf ho jata hai:

OTP (type = verify ya reset)

auth:<type>_otp:<email>: code, 300s

auth:<type>_cooldown:<email>: resend lock, 60s

auth:<type>_attempts:<email>: galat attempts, 300s

Session

refreshToken:<userId>: active refresh token ka tokenId, 7 din

Logout aur password reset par foran delete.

Rate Limit

ratelimit:<login|email|otp>:<ip>: request count, 15 minute

Redis down ho to request rokti nahi (log karke aage jane deti hai).

frontend/src/components/auth-fields.tsx

frontend/src/pages/auth/verify-email.tsx

Saare auth routes. Har route par rate limit, Zod validation aur controller. /me par authenticate.

backend/src/config/auth.config.ts
Saari timings aur limits ek jagah: token TTLs, OTP time, cooldown, attempts, unverified account TTL, bcrypt rounds, password length, body limit, rate limits.

backend/src/config/cookie.config.ts

backend/src/config/validation.ts
Zod schemas: shared email, password, otp fields se registerSchema, loginSchema, emailSchema, verifyOtpSchema, resetPasswordSchema.

backend/src/config/db.ts
MongoDB connection. Fail ho to error log karke process exit.
Used by: server.ts
backend/src/models/user.model.ts
User schema: name, unique email, password (select: false), verified status, aur verificationExpiresAt par TTL index jo unverified accounts delete karta hai.

backend/src/middlewares/auth.middleware.ts
accessToken cookie ko ACCESS_TOKEN_SECRET se verify karke req.userId lagata hai, warna 401.

backend/src/controllers/*.controller.ts

backend/src/types/express.d.ts
TypeScript ko batata hai ke Express Request par userId field hota hai, jo auth middleware lagata hai.

backend/src/utils/token.util.ts
Dual-token logic: setAuthCookies, verifyRefreshToken, isRefreshTokenActive, revokeRefreshToken, clearAuthCookies. Refresh tokenId Redis mein.

backend/src/utils/user.util.ts

backend/src/services/otp.service.ts
Redis OTP engine: crypto.randomInt se 6-digit code, expiry, cooldown, aur compare se pehle attempt counting jo parallel brute force rokti hai.

backend/src/services/mail.service.ts
Resend se verification aur reset emails. Ek shared HTML layout. "Expire in X minutes" text OTP config se banta hai.

backend/src/services/redis.service.ts
Upstash Redis REST client (@upstash/redis).
Used by: otp.service, token.util, rate-limit
